Perguntas Frequentes — FastMM4
================================

Este documento mantém perguntas frequentes de uso geral. Para a documentação
completa (instalação, compatibilidade, FullDebugMode, Boss, C++ Builder, licença)
consulte o [README.md](../README.md).

## Perguntas comuns

**Q: O FastMM4 relata vazamento de memória no encerramento. Pode estar errado?**

A: Não. Se o FastMM4 reporta que um bloco foi vazado, significa que o bloco foi
alocado mas nunca liberado. Use o `FullDebugMode` para obter mais detalhes sobre
a causa do problema.

**Q: Ao habilitar `FullDebugMode` meu aplicativo trava na inicialização. O que está errado?**

A: A biblioteca `FastMM_FullDebugMode.dll` é necessária para o `FullDebugMode`.
Certifique-se de que ela esteja na mesma pasta do aplicativo ou acessível no
caminho de busca. Binários pré-compilados estão disponíveis nas
[GitHub Releases](https://github.com/Rtrevisan20/FastMM4/releases).

**Q: Em `FullDebugMode` não há informações de debug nas stack traces, apenas endereços. Por quê?**

A: Para que a `FastMM_FullDebugMode.dll` determine informações de unidade/número
de linha nas stack traces, um dos seguintes deve estar disponível: TD32 debug
info, .map file, .jdbg file ou debug info embarcado JCL. Para que os números de
linha apareçam, também é necessário habilitar "Debug Information", "Reference
Info" e "Use Debug DCUs" nas opções do compilador.

**Q: Meu programa funciona com o gerenciador de memória Borland, mas recebo
"Invalid Pointer Operation" ou "Access Violation" com o FastMM4. Há um bug?**

A: Muito improvável. O FastMM4 faz mais verificações de ponteiro que o
gerenciador padrão e captura erros mais cedo. Compile com `FullDebugMode` para
que o erro seja levantado mais perto da origem.

**Q: Adicionei `FastMM4.pas` como a primeira unit no .dpr, mas ainda reclama que não é a primeira. Por quê?**

A: Se você usa um manipulador de exceções que modifica a ordem de inicialização
das units (como MadExcept ou EurekaLog), altere sua configuração para que o
FastMM4 seja inicializado primeiro.

**Q: Delphi 2005 falha com "Class 'TApplication', already if class map" ao substituir
o borlndmm.dll padrão pelo DLL do FastMM4. Por quê?**

A: É um bug do Delphi 2005 (QC#14007). Consulte o `FastMM4_Readme.txt` para
detalhes sobre o patch não oficial.

**Q: Estou usando o borlndmm.dll de substituição com o Delphi IDE. Quando abro
duas cópias do Delphi e fecho uma, recebo um relatório de vazamento de memória. Por quê?**

A: Ao compilar o DLL, defina a opção `NeverUninstall` em `FastMM4Options.inc`.

**Q: Estou usando o borlndmm.dll de substituição com o Delphi 2005 IDE. Quando
fecho o IDE ele permanece no gerenciador de tarefas. Por quê?**

A: Isso é um bug (QC#14070). Ao compilar o DLL, defina a opção `NeverUninstall`
para contorná-lo.

**Q: Meu programa funcionava bem, mas ao habilitar `FullDebugMode` recebo um
access violation no endereço $8080xxxx. Por quê?**

A: Você está tentando acessar propriedades de um objeto liberado. No
`FullDebugMode`, ao liberar um bloco o FastMM4 preenche a área de memória
liberada com o padrão $80. Se houver ponteiros, strings longas ou referências a
objetos dentro do objeto liberado, eles apontarão para $80808080, que está em
um espaço de endereço reservado.

**Q: Em `FullDebugMode` quando ocorre um erro as stack traces estão muito incompletas. Por quê?**

A: Certifique-se de que as informações de debug estão habilitadas no projeto e
que a `FastMM_FullDebugMode.dll` corresponde à versão do FastMM4 usada.

**Q: O FastMM4 suporta Delphi 12 Win64?**

A: Sim. Foi validado em Delphi 12 Win32 e Win64. Consulte a matriz de
compatibilidade no `README.md`.

**Q: O FastMM4 suporta Delphi Linux64 (dcclinux64)?**

A: Não. O suporte POSIX existente é para Free Pascal (Linux/macOS), não para
Delphi Linux64. O teste com `dcclinux64` falha porque a unit `Libc` não é
encontrada.

**Q: Como instalar via Boss?**

A: O repositório inclui um `boss.json`. Execute:

```sh
boss init -q
boss install github.com/Rtrevisan20/FastMM4
```

Para fixar a versão, declare no `boss.json` do seu projeto:

```json
{
  "dependencies": {
    "github.com/Rtrevisan20/FastMM4": "^4.994.0"
  }
}
```

**Q: Onde estão os binários pré-compilados?**

A: Os binários pré-compilados (DLLs de FullDebugMode, BorlndMM DLLs) foram
movidos para as
[GitHub Releases](https://github.com/Rtrevisan20/FastMM4/releases).
Consulte as notas da release para checksums e instruções de build.
